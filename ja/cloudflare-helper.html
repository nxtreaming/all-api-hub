Cloudflare シールド回避アシスタント

Cloudflare、Aliyun など、対応するサイト認証ページの処理を支援します。操作、権限、設定が許可する場合、拡張機能は認証の完了を待って安全な読み取りを再開します。手動認証後に続行できるかどうかは、実行中の操作とブラウザーセッションによって異なります。

機能概要

  • 認証の検出: 共通のリクエスト・ログイン処理で既知の認証ページと応答の特徴を識別します。401、403、429 や通常の CAPTCHA があるだけでは、シールド認証とは判断しません。
  • ポリシーに従う復旧: 許可された読み取りでは、アカウントとブラウザーの保存領域に適した一時ページを使用できます。自動タスクは全体設定と機能別設定に従い、手動操作にも権限と環境の対応が必要です。独立した認証情報を使う直接リクエストは、別のブラウザーログイン状態へ切り替わりません。
  • 重複送信の防止: ログイン、チェックイン、トークン作成など状態を変更する操作は、GET であっても認証や応答の消失を理由に自動再送しません。結果が不明なら未確認のまま保持し、認証の通過だけで操作成功とは判断しません。
  • ログイン認証の引き継ぎ: パスワードと OAuth ログインは、まずページ認証を待ちます。認証が続く場合は元のウィンドウで期限付きの続行機会を保持し、設定された通知手段を使います。バックグラウンドのウィンドウが自動でフォーカスを奪うことはありません。通知から元のページを開いて認証でき、ウィンドウを閉じるかタスクをキャンセルすると待機を終了します。

使用手順

  1. ターゲットサイトにログインし、プラグインでアカウントを新規追加 → サイトアドレスを入力 → 「自動認識」をクリックします。
  2. サイト認証中と表示されたら、ページのスクリプト処理を待ちます。手動対応の通知が表示された場合は、対応するページを開いてサイトの案内に従ってください。
  3. 続行に対応するタスクは、認証後に安全な手順を再開し、アカウントの識別情報と操作結果を別途確認します。最終的な更新・ログイン・チェックイン結果を確認してください。
  4. 設定、権限不足、非対応の環境により復旧できない場合は、該当する設定とシールド回避履歴を確認してください。レート制限や通常のネットワークエラーで無条件にウィンドウを開いて再送することはありません。

シールド回避履歴で原因を調べる

一時ページが開いた理由や、開かなかった理由を調べるには、設定 → データ更新 で サイト認証の補助 の見出し横にある シールド回避履歴 を選択します。履歴はダイアログで表示され、操作するまでは閉じています。

シールド回避に関するアカウントの警告、自動シールド回避が制限されている場合の通知、認証の失敗や一時ページの終了を示すチェックイン結果、一時ページ上のアシスタントからも シールド回避履歴を表示 を選択できます。

  1. サイト、操作、診断情報で検索したり、処理状態で絞り込んだりできます。検索と絞り込みは、保存されているすべての記録が対象です。
  2. 記録を展開すると、きっかけとなった操作とその実行元、取得できた HTTP ステータスやエラーコード、一時ページが新規作成されたか再利用されたかを確認できます。
  3. 設定や権限によってリクエストが拒否された場合は、関連設定を表示 から該当する設定を開き、必要に応じて変更します。
  4. 調査用の情報を残すには 診断の詳細をコピー を選択します。端末上の記録を削除するには、履歴ダイアログ右上のメニューから 履歴を消去 を選び、確認します。

履歴には、この端末の直近 100 件まで保存されます。新しく発生した一時ページのリクエストが記録され、アップグレード前の操作は追加されません。サイトのアドレスはオリジンのみを保存し、URL のパス、クエリパラメーター、トークン、Cookie、リクエストやレスポンスの本文は保存しません。

処理完了は、その一時ページのタスクが完了結果を返したことを示します。アカウントが再び利用できるかは、更新やチェックインなどの最終結果で確認してください。

注意事項

  • 待機期限: 1 回のページ自動確認は最大 20 秒です。手動続行に対応するログインセッションには別の有限の待機期限があり、ウィンドウを閉じるとログインをキャンセルします。
  • 権限と設定: 拡張機能が示す具体的な理由に従って、オプション権限、自動シールド回避設定、ブラウザーの対応状況を確認してください。
  • 制限の繰り返し: 429 などのレート制限ではサイトの案内に従ってください。ウィンドウの再作成や操作の再送で待機を置き換えることはできません。

よくある質問

シナリオ解決策
認証ウィンドウが閉じるタスク結果と履歴で、完了、キャンセル、タイムアウト、環境上の制限を確認してください。
「Just a moment」のまま停止続行できる通知があれば元のページを開いて認証し、期限後は最終結果を確認してください。
操作が引き続き403を返す認証や権限の理由を確認してください。送信済みの操作は、再実行する前に結果を確認してください。
ウィンドウなしで認識失敗具体的なエラーと設定を確認してください。直接リクエスト、権限不足、復旧条件に合わない場合はページを開かないことがあります。
認証ページが収まらない設定 → データ更新 → サイト認証の補助 → 認証ウィンドウのサイズで幅と高さを変更して保存します。次に新しく開く認証ウィンドウに適用されます。
